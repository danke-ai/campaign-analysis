# 电商活动效果分析与 A/B 实验 · 国庆好物节

> 6 张业务表 · 14 天活动 · SQL + Python · 漏斗分析 / 投放拆解 / 用户画像 / A/B Test

## 项目背景

某电商 App 在国庆期间开展「国庆好物节」活动（2080-09-28 ~ 10-11，共 14 天），目标是拉动用户参与和任务达标。活动结束后，参与人数未达预期，需要回答三个问题：

1. 用户在哪一步流失？
2. 投放资源是否花在了对的地方？
3. 哪些人群没有被覆盖？

本项目使用 MySQL 完成数据体检与多表关联，Python 完成指标计算与可视化，最后设计并完成 A/B 实验验证改进策略。

## 核心结论

| 环节 | 人数 | 转化率 |
|---|---:|---:|
| 曝光 | 22,572 | — |
| 点击 | 1,907 | 8.45% |
| 参与 | 489 | 25.64% |
| 达标 | 396 | 80.98% |

- **最大瓶颈在「点击 → 参与」**：每 4 个进入活动页的用户只有 1 个参与；但参与后达标率 81%，说明权益本身有吸引力，问题出在前端承接。
- **资源位曝光结构失衡**：首页图文占 81.3% 曝光、点击率仅 3.7%；首页弹窗点击率 91.3%，曝光却只占 5.6%。
- **参与高度集中在两个节点**：10-01（参与 232、达标 188）与 10-08（参与 122、达标 110）；其余高曝光日转化偏低。
- **人群差异**：画像样本内，安卓参与率 57% vs iOS 13%；新注册用户 42% vs 老用户 56%~57%。
- **A/B 实验**：首屏权益包差异化展示使活动参与率 25.64% → 29.00%（**+3.36pp，p=0.00056**），达标转化率 +3.14pp；护栏指标券后退款率无显著变化（p=0.7765）。

完整图文报告见 [`output/国庆好物节-数据分析作品集.pdf`](output/国庆好物节-数据分析作品集.pdf)。

## 分析框架

```
数据体检  →  整体漏斗  →  环节拆解  →  用户画像  →  增量与流失  →  A/B 实验
          （日期/资源位/时段）        （参与/达标/未达标）   （实验设计+Z 检验）
```

1. **数据体检**：核对 6 张表的粒度、时间范围、画像覆盖率；发现画像表 11 个重复用户并制定去重规则。
2. **整体漏斗**：按 `user_id` 去重搭建「曝光→点击→参与→达标」四层漏斗，同时计算严格嵌套口径用于交叉验证。
3. **环节拆解**：按资源位、24 小时时段拆解曝光与转化，并用线性回归量化曝光量与参与量的关系。
4. **用户画像**：对比参与、达标、参与未达标人群在性别、年龄、城市线、注册年份、平台上的结构差异。
5. **增量与流失**：对比参与用户活动前后的日均活跃次数，定位参与未达标人群。
6. **A/B 实验**：针对「点击→参与」瓶颈设计首屏权益包实验，完成样本量计算、分流、比例 Z 检验与护栏评估。

## 关键方法与口径

- **人数而非次数**：漏斗各层均使用 `COUNT(DISTINCT userid)`，避免同一用户多次曝光/点击造成虚增。
- **两种漏斗口径**：独立去重口径（22,572 → 1,907 → 489 → 396）用于定位各环节规模；严格嵌套口径（22,572 → 1,504 → 302 → 255）用于检查链路完整性，报告中均已注明。
- **重复用户处理**：画像表同一 `userid` 保留 `createday` 最新的一条；否则 JOIN 后参与人数会从 489 虚增到 495。
- **埋点缺失**：403 个用户只有点击、无曝光记录，漏斗会低估真实触达，已在局限中说明。
- **A/B 检验**：两样本比例 Z 检验（pooled SE），效应量同时给出 95% 置信区间；样本量按 baseline 25.64%、MDE 3pp、α=0.05、power=80% 计算，每组最小 3,445 人。

## 项目局限

1. 参与用户非随机分组，存在自选择偏差，活动对活跃的提升只能测算、不能直接因果归因。
2. 埋点不全：403 个用户只有点击、无曝光，漏斗低估真实触达。
3. 单活动、单平台、14 天窗口，且数据已脱敏，结论外推有限。
4. 曝光-参与相关性为线性回归，20 万曝光属于超出样本范围的外推，仅作粗估。
